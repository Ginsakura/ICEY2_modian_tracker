## ADDED Requirements

### Requirement: 常规采样 MUST 采用单行追加

当 `data.csv` 已存在且表头包含本次采样的全部列时，采集端 MUST 只读取表头行，并以一次追加写入完成本次采样；MUST NOT 读取或重写历史数据行。

#### Scenario: 表头一致时追加一条采样
- **WHEN** `data.csv` 存在、表头含本次采样全部列，追加一行采样
- **THEN** 文件行数恰好增加 1，历史行的字节内容保持不变
- **AND** 本次写入从文件读取的字节数不超过表头行长度加 2 字节

#### Scenario: 成本不随历史规模增长
- **WHEN** 同一个文件分别有 3 万行和 30 万行时各追加一行
- **THEN** 两次追加的读取字节数相同，且都不包含历史数据行

### Requirement: 表头演进 MUST 通过一次性原子重写完成

当采样包含表头中不存在的列（例如页面新增档位）或文件不存在时，采集端 MUST 先构造完整表头与历史行的补齐结果，写入同目录临时文件，再用原子替换覆盖 `data.csv`；MUST NOT 直接截断原文件后写入。重写完成后，后续采样 MUST 回到追加路径。

#### Scenario: 新增档位列
- **WHEN** 本次采样出现历史表头中没有的档位列
- **THEN** 表头末尾追加该列，全部历史行在该列补空字符串
- **AND** `data.csv` 通过临时文件原子替换生成，下一次采样恢复单行追加

#### Scenario: 重写中途失败
- **WHEN** 临时文件写入或替换失败
- **THEN** 原 `data.csv` 内容保持不变，并记录错误日志

### Requirement: 编码与行尾 MUST 与既有文件一致

`data.csv` MUST 保持 UTF-8 编码、文件开头单个 BOM、行尾 CRLF。追加写入 MUST NOT 在文件中部产生第二个 BOM。文件不存在或为空时，首次写入 MUST 先写 BOM、表头与首行。

#### Scenario: 追加不产生第二个 BOM
- **WHEN** 向已含 BOM 与 CRLF 行尾的现有文件追加一行
- **THEN** 整个文件只在开头出现一次 BOM，新增行以 CRLF 结束

#### Scenario: 首次创建文件
- **WHEN** `data.csv` 不存在或为空
- **THEN** 写入 BOM、表头与新采样行，列序为 timestamp、总人数、总金额、各档位

### Requirement: 崩溃半行 MUST 在写入前修复

若 `data.csv` 末尾不是换行符，采集端 MUST 在下一次追加前把文件截断到最后一个完整行，并记录警告；MUST NOT 在半行之后直接拼接新行。

#### Scenario: 末行不完整
- **WHEN** 文件末尾是上一次写入中断留下的半行
- **THEN** 文件被截断到最后一个换行符，随后追加的新行独占一行

#### Scenario: 文件完整
- **WHEN** 文件以换行符结束
- **THEN** 不执行截断，也不产生相关日志

### Requirement: 追加行的数值格式 MUST 与历史行一致

追加行 MUST 沿用既有格式：时间戳为 `%Y-%m-%d %H:%M:%S`；人数类数值为不带 `.0` 的整数；总金额保留页面解析出的原始数值；未解析到的值写空字符串且列位不移动。

#### Scenario: 人数解析为浮点
- **WHEN** 页面解析出的人数形如 `4647.0`
- **THEN** 写入 `4647`

#### Scenario: 总人数缺失
- **WHEN** 页面未解析到总人数
- **THEN** 该单元格写空字符串，其余列位置保持不变
